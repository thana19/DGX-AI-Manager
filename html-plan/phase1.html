1 ปัญหาของ hub เดิม

🚫
เพิ่มโมเดลเองไม่ได้

hub เดิมโหลดได้เฉพาะโมเดลที่ vendor ใส่ไว้ใน models.yaml ผู้ใช้เพิ่มเองไม่ได้เลย

❓
ไม่รู้ว่า engine รันได้ไหมจนกว่าจะโหลดเสร็จ

ความสัมพันธ์ "โมเดลนี้ต้องใช้ engine รุ่นไหน" เป็นแค่ข้อความใน note: ให้คนอ่านเอง

ตัวอย่างจริง: GLM-5.3 UD-IQ1_S = 93GB · Qwen3.8-Flash-Next = 79GB
→ ดาวน์โหลดเสร็จแล้ว engine เก่าโหลดไม่ขึ้น เสียเน็ตฟรี
⏯️
ปุ่ม "โหลด" ปุ่มเดียวทำ 2 อย่าง

ดาวน์โหลด + โหลดขึ้นแรม รวมกันในปุ่มเดียว → มองไม่เห็นว่าตอนนี้ระบบทำอะไรอยู่ หยุด/ต่อไม่ได้

2 ทางแก้ — เช็ค compat ก่อนดาวน์โหลด

📝 วาง HF repo id
↓
hf.py — ดึงรายการไฟล์ + ขนาด
↓
gguf.py — อ่าน arch จาก GGUF header (HTTP Range 256KB แรก)
↓
engines.py — เทียบ arch กับรายชื่อใน libllama.so ที่ติดตั้งจริง
↓ แตกเป็น 3 ทาง
✅ ดาวน์โหลดได้เลย
arch อยู่ใน engine ที่มีอยู่แล้ว
⚠️ ต้องอัป engine ก่อน
ระบบอัปให้เองในคลิกเดียว (เก็บ binary เก่าไว้ rollback)
❓ arch ไม่รู้จัก
เตือนผู้ใช้แล้วให้เลือกเอง (advanced mode)
ทั้งหมดนี้เกิด ก่อน ดาวน์โหลดไฟล์โมเดลจริง — ใช้แค่การอ่าน header ~256KB ไม่ต้องโหลดทั้งไฟล์

3 ข้อค้นพบที่ verify แล้ว

ข้อค้นพบหลักฐาน
HF รองรับ HTTP Range curl -H "Range: bytes=0-1048575" ตอบ 206 พร้อม content-range ⇒ ได้ header + ขนาดเต็มโดยไม่ต้องโหลดไฟล์จริง
อ่าน arch จาก GGUF header ได้จาก byte แรก ๆ general.architecture และ <arch>.context_length อยู่ต้น KV เสมอ อ่านได้ตั้งแต่ 256KB แรก (KV ทั้งหมดอ่านไม่จบใน 1MB เพราะ token list ยาว ⇒ parser ต้องหยุดทันทีที่ได้ field ที่ต้องการ)
libllama.so เก็บรายชื่อ arch ที่รองรับไว้ในไฟล์ strings libllama.so.0.3.0 | grep -x <arch> ⇒ เช็ค compat ได้ชี้ขาดจาก engine ที่ติดตั้งจริง ไม่ต้องพึ่งตารางที่คนจดเอง
⚠️ note: ของ v1 สะกด arch ผิด จดไว้ว่า qwen4_exp แต่ของจริงในไฟล์คือ qwen4exp ⇒ นี่คือเหตุผลหลักที่ต้องอ่านจากไฟล์จริง ห้ามเชื่อข้อความที่คนเขียน
HF API ?blobs=true ให้ขนาด + lfs.sha256 ทุกไฟล์ ใช้ทั้งโชว์ขนาดก่อนโหลด และ verify ไฟล์หลังโหลดเสร็จ
ไฟล์ quant อยู่ในโฟลเดอร์ย่อย เช่น UD-IQ1_S/, MTP/, BF16/ ⇒ จัดกลุ่ม quant ต้องดู path ไม่ใช่แค่ชื่อไฟล์

7 ความปลอดภัย / ทางถอย

  • รันพอร์ต 9001 คู่กับ hub เดิม :9000 — ไม่แตะ :9000 เด็ดขาด
  • ไม่แตะ instance ที่รันอยู่บน :8000
  • state แยกที่ ~/.aiserver2/ (คนละที่กับ ~/.aiserver/ ของ hub เดิม)
  • ทางถอย = ปิด :9001 แล้วลบ ~/aiserver2 — ระบบเดิมไม่เคยถูกแตะ
